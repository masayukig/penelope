# 0053. 目的に沿った問いで記憶を評価する CLI を持つ

- Date: 2026-11-21
- Status: Accepted

## Context

夜の活動の記録には、段の成否と記憶の変更量が載る。変更量を見ても、記憶を使って配置の役目に必要な問いに答えられるようになったかは分からない。評価には、問いを揃えたうえで、日中の会話から得た情報と記憶から取り出せた知識を区別し、記憶を育てる前後を比較できる入口が要る。

## Decision

- 評価は Web UI に載せない。手元から起動する CLI を sandbox の中で動かし、`PURPOSE.md` の「答えられるべき問い」を使う。問いの一覧は見出しと箇条書きで持つ。過去の時点の記憶にも同じ問いを投げ、結果を問いごとに比較できるようにする。
- 問いごとに本体とは別の、人格や会話の履歴を引き継がない新しいセッションを使う。モデルは日中と同じ経路を使い、道具は対象の記憶を読むものだけに限る。記憶の書き込み、他のファイルの閲覧、shell、投稿などの道具は渡さない。指定した記憶や問いを読めない、または読み取り範囲を守れないときは評価を実行しない。過去の時点を用意するために現行の `/memory` を切り替えない。
- 答え、読んだファイル、道具の利用回数、トークン数、所要時間を記録する。結果は `/memory` に書かず、sandbox の私的な置き場に残す。標準出力の既定は数値の指標だけで、問い、答え、ファイル名は出さない。オーナーが本文を見るには明示的に指定する。合否は付けず、答えの質はオーナーが判断する。

### 本 ADR で決定しないこと

- CLI の名前と引数、過去の記憶を用意する方法、問いの節の正確な形式と結果の保存形式（委譲先: sandbox の CLI と runner の実装）
- 評価の結果の保存期間（委譲先: オーナーの運用）
- 本番の写しで夜の全段を回す道具（委譲先: 必要になった時点の別 ADR）

## Consequences

- 本体のセッションと記憶を変えずに、問いごとに過去と現在の記憶を比較できる。既定では中身を端末に出さず、費用や探索量の変化を見られる。
- 評価にはモデルの利用が必要で、読んだ記憶は日中と同じモデル経路の接続先に送られる。結果に記憶由来の情報が含まれるので、保存した結果や明示的な本文出力はオーナーが扱う。
- 結果は問いの選び方とモデルに依存する。道具や会話を含む実際の仕事の評価や、正答を自動判定する回帰テストの代わりにはならない。
