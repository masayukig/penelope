# 0046. モデル要求では接続先の上限に合わせて古い画像を省き、失敗を次のターンに伝える

- Date: 2026-11-21
- Status: Accepted

## Context

画像を 1 要求に 3 枚までしか受け取らない接続先で、セッションに画像が積み上がると、モデルが要求を 400 で断り続けて会話が止まった。Pi はセッションの履歴を次の要求にも載せるので、次の発言に画像がなくても同じ制限に当たる。終わったターンを畳んでもユーザーの画像は残る。また、要求がエラーで終わったモデルの応答は、モデルへ送る履歴から Pi の変換で外れる。活動の記録でオーナーには失敗が見えるが、エージェントには理由が伝わらない。

## Decision

- 1 回のモデル要求の画像の上限は、接続先ごとにモデル定義と同じ場所で設定する。上限を設定していない接続先の文脈は変えない。
- 本体・サブエージェント・夜のターンのモデル要求で、畳み込みなどを経て送る文脈に残った画像が上限を超えるときは、新しい画像を残し、古い画像から文の印に置き換える。元ファイルの場所が分かれば印に添える。セッションの記録は書き換えない。
- 本体のモデル要求が失敗して終わったターンの理由は、画像に関わるものに限らず、同じセッションの次のターンに短く添える。夜の振り返りは日中のセッションを使うため対象に含む。別のセッションで動く夜の係には引き継がない。配送と ack の取り扱いは変えない。

### 本 ADR で決定しないこと

- 設定項目の名前、印と失敗の知らせの文面、文の長さ（委譲先: sandbox 向けの口の仕様「モデルの設定」）

## Consequences

- 画像が積み上がっても、接続先に既知の画像上限を超えない文脈を送れる。画像は元の記録に残るので、制限のない接続先に切り替えれば、履歴にまだある画像を再び送れる。
- エージェントは省いた画像の細部を見直すときに、元ファイルを開き直す必要がある。文脈の途中が変わるため、接続先のキャッシュが使えなくなる場合もある。
- 失敗の知らせは次に通った要求で初めて届く。知らせを添えるだけでは、接続先が要求を断り続ける状況は解消しない。

## Alternatives Considered

- **400 の応答から枚数を推測して再試行する**: 接続先ごとにエラーの文面が違い、書き方の変更で効かなくなる。既知の上限は配置で明示し、失敗は次のターンに伝える。
