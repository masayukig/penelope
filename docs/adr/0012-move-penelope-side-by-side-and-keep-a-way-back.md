# 0012. なつみベースのペネロペからは、並べて立ち上げてから切り替え、戻せる形を保つ

- Date: 2026-11-14
- Status: Accepted

## Context

ペネロペは、今は natsumi の 1 インスタンスとしてオーナーのクラスタで動いている。ペネロペは毎日の運用の係であり、記憶（`/memory`）を毎日育てている。止めている間は、警報の受け取りもほかのエージェントからの頼みごとも止まる。

ペネロペには、移すべきものが記憶のほかにもある。GitHub のアカウントとその token、VM の API の token、クラスタを読むための RBAC とアドミッションの床、A2A の受け口と送り手の allow-list、監視の警報の webhook である。

penelope は新しい形なので、最初から今のペネロペと同じに動く保証は無い。

## Decision

移行のあいだ、次の条件を守る。

- **並べて確かめる。** penelope のペネロペは、今のペネロペとは別の場所（別の namespace と別の URL）に置き、今のペネロペを止めずに確かめる。
- **記憶の書き手は常に 1 つ。** 記憶を写すときは、写し元のペネロペを止めてから写す。今と新しいペネロペが、同じ記憶を同時に書き進めることはない。
- **記憶は履歴ごと写す。** `/memory` の形は互換なので（ADR-0006）、中身を書き換えずに git の履歴ごと持ち込む。
- **権限は新しい ServiceAccount に付け直す。** 読みの RBAC と床は、今のペネロペの ServiceAccount を共有せず、新しい ServiceAccount に同じものを付ける。
- **戻せる形を保つ。** 切り替えた後も、今のペネロペの配置はしばらく消さない。戻すときは、新しいペネロペを止め、記憶を写し戻してから今のペネロペを動かす。
- **本番に触る各段は、そのつどオーナーの承認を取る。**
- 今のペネロペの配置を片付けるのは、新しいペネロペで様子を見た後とする。

### 本 ADR で決定しないこと

- 移行の工程と日取り（委譲先: 移行のタスクの記録）
- 新しい配置の namespace と URL（委譲先: 配置のリポジトリ）
- 様子を見る期間と、片付けてよいと判断する条件（委譲先: 移行のタスクの記録。オーナーが決める）

## Consequences

- 新しいペネロペを本番の外で確かめられる。問題があれば、今のペネロペに戻せる。
- 記憶の書き手を 1 つに保つので、記憶が 2 つに分かれて食い違うことがない。
- 一方で、切り替えのあいだはペネロペが止まる。止めて写す時間のあいだ、警報や頼みごとは受けられない。
- 並べているあいだは、鍵と権限が 2 か所にある。今のペネロペを片付けるまで、守る場所が倍になることを受け入れる。
