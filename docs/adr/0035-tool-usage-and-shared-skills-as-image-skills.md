# 0035. 道具の使い方とどの配置にも同じ skill は sandbox の image に skill として入れ、オーナー・記憶の後に並べる

- Date: 2026-11-17
- Status: Accepted（image の skill の一覧への載せ方は ADR-0042 で一部置き換え）

## Context

コネクタは、Sentinel のホストの登録と、その使い方の文書の組である（ADR-0020）。ADR-0020 は文書の中身を配置のリポジトリに置くと決めたので、このリポジトリは使い方の文書を 1 つも持っていない。

配置を 4 つ（ペネロペ・なつみ・ミャオ・アキ）作ってみると、コネクタの文書の大半は、どの配置でも同じ「道具の使い方」だった。

- Slack の文書は 3 つの配置にあり、違うのはワークスペースの名前と token の環境変数の名前だけで、`slackctl` での読み方・投稿の仕方・外の人の書いたものの扱いは同じ写しである。
- 絵を描く（`sdctl`）文書と、ほかのエージェントに A2A で頼む（`a2a` の CLI）文書も、宛先を除けば同じことを書いている。GitHub の文書の `gh`・`git` の使い方も、アカウントを除けば配置によらない。

道具はこのリポジトリの中にある（`slackctl`）か、このリポジトリの sandbox の image が版を決めて入れている（`sdctl`・`a2a`・`gh`）。それでも使い方の写しは配置の側にあり、道具の版に合わせて配置ごとに直さなければならない。また、私的な配置のリポジトリを持たない人は、公開のこのリポジトリだけでは道具の使い方を渡せない。natsumi を使っている人が、このリポジトリだけで移れるようにしたい。

skill にも同じことが起きている。skill は、名前・説明・場所だけがシステムプロンプトの一覧に載り、本文はエージェントが要るときに読む形である。runner は、配置が読み取りで渡すオーナーの skill と、記憶の `skills/` を並べて読み、同じ名前ならオーナーの方を一覧に載せる。自分の姿で絵を描く skill `self-portrait` と、目標と今日の計画を扱う skill `goals` は、どの配置でも同じものを、配置がオーナーの skill として置いている。

## Decision

本 ADR は、ADR-0020 の Decision「中身は配置が持つ」のうち、このリポジトリが規則と runner だけを持つとした点を置き換える。コネクタが登録と文書の組であること、文書の形と置き場、一覧の出し方、書き損じの扱いは変えない。

### 道具の使い方は image の skill にする

- このリポジトリは、image が入れている道具とこのリポジトリの道具について、どの配置でも同じ使い方を skill として持ち、sandbox の image に入れる。配置の設定が無くても、つねに一覧に載る。2026-11-19 追記: 一覧への載せ方は ADR-0042 で一部置き換え。既定は変えず、配置が一覧の対象を選べるようにする。
- image の skill は、配置の値（ホスト・ワークスペース・アカウント・宛先・サロゲートを持つ環境変数のうち配置が決めるもの）を持たない。それは配置のコネクタの文書にある、と指す。道具そのものが決めている設定の名前は、道具の使い方として書いてよい。
- コネクタは ADR-0020 のまま、配置だけが持つ。配置のコネクタの文書は、その配置だけのこと（ホスト、サロゲートを持つ環境変数、ワークスペースや宛先、その配置だけの決まり）を書く。image の skill とコネクタは名前で突き合わせない。別の一覧に、それぞれ載る。

### どの配置にも同じ skill も image に入れる

- どの配置でも同じ skill（`self-portrait`・`goals`）も、このリポジトリが持ち、sandbox の image に入れる。

### 重ね方は skill の並びの 1 つだけ

- runner は、オーナーの skill、記憶の `skills/`、image の skill を、この順で並べて読む。同じ名前が 2 か所以上にあれば、この順で先にあるものが一覧に載る。
- image の skill は既定であり、配置はオーナーの skill で、エージェント自身は記憶の skill で、同じ名前を置き換えられる。
- システムプロンプトは、image の skill の場所と、同じ名前のときにどれが載るかを、事実として伝える（ADR-0008 の Decision「事実と環境を伝え、やり方はエージェントに任せる」）。

### 書き方

- image の skill の文は英語で書く（このリポジトリの AGENTS.md「Prompts」）。記憶のファイルの形を決める見出しや印（`goals` の節の見出しなど）は、natsumi の記憶と同じに読めるよう、natsumi が書いてきた日本語のままにする（ADR-0006）。

### 守る対象と、失敗したときの倒し方

- image の skill は公開のリポジトリにあるので、配置の値も、鍵の値も、サロゲートの値も書かない。守る対象は ADR-0004 と同じく本物の鍵であり、本 ADR はそれを変えない。鍵の差し替えは、今までどおり Sentinel の設定だけで決まる。
- image の skill は sandbox から書き換えられない。エージェントが直したいときは、同じ名前の skill を記憶に置く。
- image の skill が読めなければ、その skill が一覧に載らないだけで、セッションは止めない。

### 本 ADR で決定しないこと

- image の中の置き場と、runner の読み方（委譲先: [Pod の形の仕様書](../pod.md) の「volume」）
- image に入れる skill の個々の中身（委譲先: このリポジトリの `packages/runner/image/skills/`）
- 今ある配置のコネクタの文書を、その配置だけのことに縮める時期と、配置が置いている同じ名前のオーナーの skill を外す時期（委譲先: 配置のリポジトリ）

## Consequences

- 配置の設定が無くても、エージェントは最初のセッションから、image の道具の使い方と、どの配置にも同じ skill を知れる。公開のこのリポジトリだけで、それがそろう。
- 道具の版を上げるときに、使い方を同じ変更で直せる。配置ごとの写しを直して回らずに済む。
- 配置のコネクタの文書は短くなる。一方で、今ある配置の文書は道具の使い方を持ったままなので、縮めるまでは同じ使い方をコネクタと skill の 2 つで読むことになる。名前で突き合わせないので壊れはしないが、食い違えばどちらが正しいかはエージェントが読んで判断することになる。
- 同じ道具のことが、コネクタ（配置のこと）と skill（使い方）の 2 か所に分かれる。エージェントは、両方を読んで 1 つの使い方にする。
- オーナーや記憶の skill が image の skill に勝つので、image の skill を直しても、同じ名前を置いている配置や記憶には届かない。

## Alternatives Considered

- **道具の使い方をコネクタの文書として image に入れ、配置の文書と名前で突き合わせて 1 つの項目にする**: 配置の文書を縮めても image の文書が残る点は良いが、ホストを持たない「コネクタ」ができ、登録と文書の組という ADR-0020 の形が崩れる。突き合わせの規則（どちらの説明とホストを載せ、どちらが勝つか）も新しく要る。skill の並びという、すでにある 1 つの重ね方で足りる。
- **同じ名前のコネクタなら配置の文書だけを載せる**: 配置の文書を縮めると、その名前の image の文書が隠れたまま、使い方が届かなくなる。
- **image の skill をオーナーの skill より先に置く**: 今ある配置が置いている同じ名前の skill が使われなくなり、配置ごとの直しが効かなくなる。
