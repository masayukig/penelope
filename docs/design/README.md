## 1. 考え方

Meta の Muse の構成（見た目ではない）を参考にした。会話が家で、1 本の長いやりとりが中心にある。その周りを 2 つに分ける。

| | 左（PC はレール、スマートフォンはメニュー） | 右（PC はパネル、スマートフォンは下からのシート） |
|---|---|---|
| 意味 | **場所を変える**。押すと真ん中が入れ替わる | **いまのエージェント**。会話の横に出るだけで、会話は消えない |
| 時制 | 過去と蓄え | 現在 |
| 中身 | 会話、活動の記録、記憶、出来事と予約、設定 | アバターと expression、承認待ち、今の様子（今のターンの途中経過） |

- 承認待ちは「エージェントがいま止まって待っている」ことなので右に置く。答え終わった承認の履歴は、左の「活動の記録」に入る。
- 新しい承認待ちの印は、どの画面でもアバターの右肩に出る（キャンバスでは点線の丸で場所だけ示した）。
- サブエージェントが増えたら、右のパネルにエージェントごとの欄が縦に並ぶ（今は「（本体）」の見出しだけ置いてある）。
- 見た目の方向は「ゆったり見せる。ただし必要な情報には 1 操作で届く」。

## 3. PC（`Hybrid.dc.html`）

横に 3 つ並ぶ。

1. **左のレール**: 会話、活動の記録、記憶、出来事と予約、設定。Astryx の `SideNav` をそのまま使い、**最初は畳んだ状態（アイコンだけ）** にする。広げるのは `SideNav` の畳むボタンで。今いる場所は薄い地で示す。最初の版で中身があるのは「会話」だけで、ほかは後の波。「出来事と予約」には、後から予約の一覧を置いた（12 章、[ui-api.md](../ui-api.md) の「予約」）。
2. **会話**（残りの幅。中身は最大 720px で中央寄せ）: 上に高さ 56px の帯があり、右端に「状態の点と文字・名前・アバター（36px）」のボタンがある。押すと右のパネルが開閉する。その下が時系列と入力欄。
3. **右のパネル**（幅 380〜440px、開け閉めできる。最初は開いている）: 上から順に、アバターの舞台（120px のアバターと expression の札）、承認待ち、サブエージェント（いるときだけ）、本体の今の様子。タブはない。

## 4. スマートフォン（`Phone.dc.html`、`PhoneSheet.dc.html`）

- ヘッダーの帯はない。会話は画面の上端まで伸び、その上に **アバター（72px）が上の中央に浮く**。アバターの下に expression の札。名前は出さない。会話はアバターの下を流れる。
- 左上にメニューのボタンが浮く（丸い地）。開くと「場所」（会話、活動の記録、記憶、出来事と予約、設定）。
- 入力欄のすぐ上に **状態の帯**（点、状態、いま使っているツール）。親指が届く位置。
- アバターか状態の帯を押すと、下から **シート**が出る。中身は PC の右のパネルと同じ（アバター 88px、承認待ち、今の様子）。
- 文字は 16px を基本にする（neutral の theme が、タッチで狭い画面のときにそうする）。
- 会話の左右は、入力欄と状態の帯に揃えて画面の端から 16px にする（2026-11-15、本人）。エージェントの返事は吹き出しなしでその幅いっぱいに流し、オーナーの吹き出しは右寄せのまま幅の上限を 85% にする。時系列の密度は `compact`。
- 入力中（`PhoneKeyboard`）は、入力欄がキーボードの上に乗る。キャンバスではキーボードを描かず、領域だけ空けてある。
- ホーム画面に置いて開く（PWA）前提。

## 5. 会話と今の様子の中身

### 会話（`Talk.dc.html`）

- 新しいものが下。日付の区切り（「今日」）。
- **エージェントの返事**: 枠のない文章を左に。上に、アバター（28px）、名前、その返事の expression（文字）、きっかけの札（例「予約・毎朝 9:00」。Slack のメンションやアラートのときも同じ場所。長いときは 13 章）。下に時刻。
- **オーナーのメッセージ**: 薄い地の吹き出しを右に。添付の画像は吹き出しの上に縮小して出し、押すと大きく見える。画像でないファイルは名前の札。読み込み直した後も、backend の写しで同じように出る（[ADR-0034](../adr/0034-images-the-owner-sends-copied-by-the-backend.md)）。
- **返事の画像**（[ADR-0032](../adr/0032-images-attached-to-a-reply-copied-by-the-backend.md)）: 返事の文の下に、送られた順に縮小して並べる（オーナーの添付と同じ `Thumbnail`。幅 200px・高さ 160px、狭い画面では折り返し、画面の幅を超えない）。押すと `Lightbox` で大きく見え、拡大もできる。PC とスマートフォンで同じ。
- **考えている最中にオーナーがもう 1 通送ったとき**: すぐ時系列に並び、時刻の横に「考えている最中に届きました」と添える。今の様子の流れには「割り込み」として出る。
- **エージェントが考えているあいだ**: 時系列の最後に 3 つの点。
- **入力欄**: 角の丸い白い枠。複数行の文字、左下に添付のボタン、右下に送るボタン。
- **添付を付けたとき**（`attach`）: 入力欄の枠の中、文字の行の上に並べる。画像は 64px の縮小表示、画像以外はファイル名と大きさの札。それぞれ右肩の × で外す。スマートフォンでは横にスクロールする。
- **空のとき**（`mode=empty`）: 中央に文字だけ（「まだ会話はありません」「下の欄から話しかけてください。」）。
- **接続が切れたとき**（`mode=offline`）: 入力欄の上に知らせ（「接続が切れました。つなぎ直しています。書いたものは、つながってから送られます。」）。PC のヘッダーの状態は「接続なし」になる。この文言は、送信を溜めておく動きを前提にしている。そうしないなら文言を変える。

### 今の様子（`Activity.dc.html`）

- 一番上に状態: 「考えている」「ツールを使っている」「待っている」。点（8px）と **14px の太字** で示す（色だけにしない）。見出しの大きさにはしない。
- その下に、今のターンの途中経過を、ブロックが閉じるごとに上から順に流す。
  - ターンの始まり（時刻と、きっかけ）
  - 思考: 普段は 2 行に畳み、「全文を開く」で全部
  - ツールの呼び出し: 名前と引数を等幅で（例 `bash: kubectl get prometheus -n monitoring -o yaml`）
    - 引数は JSON のまま出さず、呼び出しが何に向いているかを出す: `bash` はコマンド、`grep`・`find` は探すもの（場所があれば `… in 場所`）、`read`・`edit`・`write`・`ls` はパス。ほかのツールは、文字列の値が 1 つならそれ、そうでなければ短い JSON。何も無ければ名前だけ。今の様子・状態の帯・サブエージェントの今の 1 行で同じ形
  - ツールの結果: 普段は畳み、「結果を開く」で等幅の枠（高さに上限、中でスクロール）
  - 割り込み: 色のついた地で目立たせる
  - 書いている途中のブロックは 3 つの点
- 待っているとき（`idle`）は流れを出さず、「いまは何もしていません。次の出来事を待っています。」

## 6. アバター

- 部品は 1 つ（`AgentAvatar`）。受け取るのは **expression と大きさ** だけ。画像と名前は設定から入る（コードに「ペネロペ」を書かない）。
- expression ごとに絵を差し替える（2026-11-14、本人の決定でキャンバスの時点の「差し替えない」を覆した。[ADR-0016](../adr/0016-show-the-avatar-and-expression-from-the-first-web-ui.md)）。絵は設定で選んだアバターの表情のアイコンで、知らない語や表情が無いときは neutral。大きく出すところ（札つき）には、表情の語を文字の札で添える。
- 返事の名前の横は、その返事の expression の絵。舞台・ヘッダー・スマートフォンで浮くアバターは、考えている・ツールを使っているあいだは thinking の絵、待っているときは、いちばん新しい返事の expression の絵で、3 分たつと neutral に戻る（どちらもなつみと同じ。2026-11-14、本人の決定）。
- ゆくゆく 3D モデルなどに替えるときは、この部品の中身だけを差し替える。画面の側は触らない。
- 出る場所と大きさ: PC の右のパネルの舞台 120px（札つき）、PC のヘッダー 36px、スマートフォンで浮く 72px（札つき）、シートの舞台 88px（札つき）、返事の名前の横 28px（expression は名前の横に文字で）、ログイン 88px。
- expression の語は 9 種: neutral・happy・laughing・surprised・thinking・worried・sad・sleepy・angry（アバターの表情のアイコンと同じ）。キャンバスの丸い絵と札の語（「考え中」「ほっとした」）は仮のもの。

## 7. `.dc.html` の読み方

- Claude design の「Design Component」という形の HTML。単体ではブラウザで開けない（`support.js` はキャンバスの側にある）。**値を読むための資料**として使う。
- 見た目はほぼすべて、要素のインラインの `style` に書いてある。余白、大きさ、角丸はそこから読む。
- 色は Astryx の変数名そのまま（`var(--color-background-surface)` など）。値は各ファイルの一番外の要素で `light-dark(明, 暗)` として定義してあり、`@astryxdesign/theme-neutral` 0.7.16 から写した。
- `{{名前}}` は末尾の `renderVals()` が返す値。`<sc-if value="{{x}}">` は条件つきの表示。`<dc-import name="Talk" …>` は `Talk.dc.html` をその場に置く、という意味で、ほかの属性は引数になる。
- 文言とデータ（Pod の名前、時刻、ファイル名など）はすべて例。

## 11. サブエージェントの欄（2026-11-15 追記）

サブエージェント（[ADR-0022](../adr/0022-sub-agents-run-by-the-runner-and-talk-only-to-the-main-agent.md)）を UI でどう見せるかへの答え。部品は `Agents.dc.html`。

### 決めたこと

1. **途中経過は最新の 1 行だけ出し、押すと流れが開く。** サブエージェント 1 人が 1 つの枠（細い線で囲む）。枠の中は上から、
   - 1 行目: 状態の印、名前（等幅・太字）、状態の文字（「考えている」「ツールを使っている」「止まって待っている」）、開く印
   - 2 行目: 目的（1 行。入りきらなければ末尾を省く）
   - 3 行目: いまの 1 行（等幅。例 `bash: kubectl get nodes`）。**走っているときだけ**
   - 枠を押すと、その場で下に流れ（目的の全文、ターンの始まり、思考、ツール、書いている途中）が開く。**開けるのは一度に 1 人**（別の人を開くと前の人は閉じる）。
2. **止まって待っている人は、色では目立たせない。** 印を丸（走っている）から「一時停止」の形（縦 2 本）に変え、文字で「止まって待っている」と出す。見出し「サブエージェント」の右に「走っている 2 ・ 待っている 1」と人数を出す。オーナーは UI から操作できないので、警告の色は使わない。
3. **縦に並べ、本体だけ大きいまま。** 右のパネル（スマートフォンではシート）の並びは、アバターの舞台 → 承認待ち → サブエージェント → 本体の今の様子。本体の流れは下に伸び続けるので、高さの決まっているものを上に置く。並び順は起こした順で、状態が変わっても入れ替えない。
4. **閉じたサブエージェントは、パネルには残さない。** 後で左の「活動の記録」から辿れるようにする（今回は置き場所だけ）。
5. **0 人のときは欄ごと出さない**（空の枠も見出しも出さない）。
6. **パネルやシートを閉じているとき**: PC はヘッダーの「状態・名前・アバター」のボタンの中、名前の左に札「サブ 3」を出す。スマートフォンは入力欄の上の状態の帯の右寄りに同じ札を出す。数は走っている人と待っている人の合計。0 人のときは札を出さない。
7. **操作の部品（止める・閉じる・話しかける）は置かない。**

### 6 人のとき

## 12. 予約の一覧（2026-11-17 追記）

予約の一覧（依頼文、cron か 1 回きりの日時、次に動く時刻、「取り消す」が 1 行ずつ並ぶ画面）を描き直したもの。部品は `Schedule.dc.html`。画面が受け取る情報は今のままで足りる（依頼文、cron または 1 回きりの日時、次に動く時刻。[ui-api.md](../ui-api.md) の「予約」）。

### 決めたこと

1. **次に動く時刻の順に並べ、日ごとに区切る。** 区切りの見出しは日付（12px の太字、薄い色、下に細い線）。明日のものは「明日 ・ 11月18日(水)」、今日のものは「今日 ・ …」、それ以外は日付だけ。年が違うときは年も書く。
2. **行の左端に時刻**（幅 56px、16px の太字、数字は等幅）。「次は」という言葉は出さない（並び順が次に動く時刻そのものなので）。
3. **依頼文を見出しと本文に分ける。** 最初の「。」までを見出し（15px の太字。折り返してよい）、残りを本文（13px、薄い色、1 行で末尾を省く）にする。「。」が無ければ全文を見出しにし、本文は出さない。見出しの末尾の「。」は取る。
4. **行を押すと全文が開く。** 本文の 1 行の省略が外れ、全部が折り返して出る。開けるのは一度に 1 行。
5. **繰り返しを言葉で書く。** 繰り返しのアイコン、言葉（「毎日 6:00」「毎週 日曜 18:00」「毎月 1日 9:00」「毎年 1月5日 9:00」）、元の cron（11px の等幅、薄い地の札）の順に並べる。1 回きりの予約は「1 回だけ」とだけ書き、アイコンも cron も出さない。
   - 言葉にするのは、毎日・毎週（曜日 1 つ）・毎月（日 1 つ）・毎年（月と日 1 つずつ）の 4 つで、分と時が 1 つの数のときだけ。毎日の回は時刻によらず「毎日」と書く。ほか（`*/30`、範囲、並び、曜日と日の両方など）は言葉を出さず、アイコンと cron の札だけを出す。
   - cron は backend の時間帯で読まれる式なので、言葉は式の数をそのまま書く（ブラウザの時間帯に換算しない）。行の時刻と日付の区切りは、次に動く時刻をブラウザの時間帯で書く。
6. **「取り消す」は静かにする。** 地の色なし、細い枠、薄い色の文字（13px）。高さは 44px を保つ。
7. **「取り消す」を押したら確認を 1 回はさむ。** 確認には見出しと、繰り返しか 1 回きりか（繰り返しは言葉か cron）を出し、エージェントには知らせないことを添える。確認の見た目は前のまま（`AlertDialog`）。
8. **見出し「予約」の横に件数と次の 1 件**（「7 件 ・ 次は 明日 6:00」）。
9. **中身の幅は最大 720px で中央寄せ**（会話と同じ）。PC では右のパネルはそのまま出る。
10. **スマートフォン**では同じ部品をそのまま使う。浮いたアバターに隠れないよう、上に 140px の余白を入れる（`pad`）。
11. **左の「出来事」は「出来事と予約」にする**（`Hybrid.dc.html`）。予約の画面のとき、そこを選んだ色にする。

予約が 0 件のときは、前のまま「予約はありません」と出す（絵にはしていない）。

### 実装するときの注意

- **繰り返しの予約は 1 行だけ出す。** 次に動く 1 回の日付の下に置く。毎朝の予約を、毎日の区切りの下に何度も出すことはしない。
- **日付の区切りと「今日」「明日」は、ブラウザの時間帯で決める。** 絵は、cron を評価しているのと同じ時間帯で決める前提で描いてある。UI は backend の時間帯を受け取らないので、ブラウザの時間帯が backend と違うと、区切りの日付と cron の言葉の時刻が食い違って見えることがある（動く時刻そのものは `next_at` のとおり）。
- **見出しと本文の分け方は、最初の「。」だけを見る。** 英語の「.」では切らない（パスやファイル名に含まれるため）。最初の文がとても長いときは、閉じている間は見出しを 2 行で省き、開くと全部を出す。
- **見出しに含まれる「（毎朝6:00 JST）」のような言葉は、勝手に削らない。** 繰り返しの言葉と重なって見えるのは許す。
- **cron を言葉にするのは、確実に言えるものだけ**（5 の 4 つ）。言葉にしたときも、cron の札は必ず残す（正しいのは cron の側）。
- **行を開くボタンと「取り消す」は、入れ子にせず横に並べる。** 「取り消す」を押したときに行は開閉しない。「取り消す」の読み上げ名には見出しを入れる（「「朝の予定確認」を取り消す」）。
- **取り消したあと**: その行を消す。区切りの下が空になったら、区切りの見出しも消す。件数と「次は」も更新する。開いている行は、行の id で開いたままにする。
- **スクリーンショットをリポジトリに置くときは、予約の中身に注意する。** 依頼文には個人的な内容が入りうる。

### Astryx の部品

| 画面のもの | 実装 |
|---|---|
| 一覧と行 | 自前の `ul` と `li`。`List`（`ListItem`）は行の中に押せるものを 2 つ（開く・取り消す）置く形に合わない |
| 行を押して開く | 自前のボタン（`aria-expanded`）。`Collapsible` は閉じたとき中身を隠すので、本文を 1 行出しておく形に合わない |
| cron の札 | `Code` |
| 「取り消す」 | `Button`（`ghost` に細い枠）。確認は `AlertDialog` |
| 見出し | `Heading`。日付の区切りは `h2` |

## 13. きっかけの印が長いとき（2026-11-17 追記）

会話の返事の、名前の横に出る「きっかけの印」（例「予約 ・ 毎朝 9:00」）の出し方。実際には次のような長いものが来て、折り返して見づらかった。

- `alertmanager ・ [FIRING warning] KubeJobFailed: Job failed to complete.`
- `自分から ・ 2件の独立レビューを完了し、証跡と投稿案を保存しました。**いずれも承認相当、今回の差分に起因する blocker は見つかりません。**`（self の出来事。サブエージェントが返した文と見られる）

見本は `Talk.dc.html` の `mode="trigger"`（`TalkTrigger`、`TalkTriggerPhone`、`TalkTriggerPhoneLong`）。

### 決めたこと

1. **印は必ず 1 行。折り返さない。** 入りきらない分は末尾を「…」で打ち切る。
2. **全文を開く手段は付けない。** 押しても何も起きない（矢印も、ポップアップも、マウスオーバーの表示も、その場で開く枠も無し）。全文はターンの詳細の画面で見られるので、ここでは要らない。
3. **印の中は「種類 ・ 中身」。** 種類（`alertmanager`、`自分から`、`予約` など）は太字で、必ず全部出す。打ち切られるのは中身の側だけ。
4. **幅は固定しない。** 印は名前の行の残りを右端まで使う。中身が短いときは中身の幅で止まる（地の色を右端まで伸ばさない）。
5. **アバター・名前・表情のかたまりが行の半分を超えたら、印は次の行に下がる。** 下がった行では、印は横幅いっぱいまで使える（そこでも 1 行で打ち切る）。
6. **名前がとても長いときは、名前も 1 行で「…」にする。** 行からはみ出さない。
7. **印の中では Markdown の記号を外す**（`**太字**` → `太字`）。印の中で書式は付けない。
8. 短い印（「予約 ・ 毎朝 9:00」）は今までどおり。打ち切られないだけで、同じ部品。

### 検討してやめた案（戻さないこと）

- 印を種類だけにして、押すとポップアップで全文: 返事の本文を隠す。長い文に向かない。スマートフォンで出る位置が不安定。
- 押すと名前の行の下に全文の枠が開く: 印と枠のつながりが見えにくかった。
- マウスオーバーで全文: スマートフォンに無い。長い文は読みにくい。
- 幅の上限を px で固定（PC 280px、スマートフォン 180px）: エージェントの名前が長いと破綻する。

### 実装するときの注意

- **幅を測る処理は要らない。CSS だけで組める。** 名前の行は折り返す flex、アバター・名前・表情のかたまりは縮められて名前だけが「…」になり、印の入れ物は残りを使って `min-width: 50%` を持つ。この 50% が「半分を超えたら下がる」を決めている（正確には、行の半分からすき間の 8px を引いた幅）。印は入れ物の中で中身の幅に止まり、種類は縮めず、中身だけを打ち切る。
- **Astryx の `Badge` は使わない。** 中で幅と折り返しを決めていて、上の指定が効かないため。素の要素で組み、見た目（薄い地、丸い角、12px）だけ合わせる。
- **打ち切りは CSS で行い、文字列は切らない。** 全文を DOM に残すので、読み上げでは全文が読まれる。`title` 属性は付けない（マウスオーバーの表示はやめたので）。
- **中身に改行が入っていたら空白 1 つに置き換える。** 1 行に収めるため。
- 見本では返事の横幅が親の 88% までなので、印が使える幅もその中になる。実装では、返事の横幅の中で同じように決まる。
- **「自分から」がサブエージェントの結果のとき**は、中身を返ってきた文ではなくサブエージェントの名前にするほうが良い（`サブエージェント ・ cluster-test`）。ただし、出来事がどのサブエージェントからのものかを UI が受け取れるかは確かめていない。**未決。** それまでは今の形（`自分から ・ 文の先頭…`）のまま。
- **キャンバス上の表示は確かめていない。** 崩れに気づいたら、絵ではなくこの章の文章を正とする。

### 例として置いたもの

見本の返事の本文、時刻、表情、長い名前「ペネロペ・クラスタ管理担当」は例。きっかけの 2 つの文は、実際に来たものを本人が示したもの。

## 14. ファイルを落として添付するとき（2026-11-17 追記）

キャンバスに無い見た目なので、今の画面の調子と Astryx の部品に合わせて実装で決めた。

### 決めたこと

1. **落とす先は会話の画面の全体。** 時系列の上でも入力欄の上でもよい。PC の左のレールと右のパネルは含まない。落としたファイルは、添付のボタンで選んだのと同じく入力欄の添付の並びに入る。種類・大きさ・数の扱いもボタンと同じ。
2. **ファイルを画面の上に持ってきている間だけ、会話の画面の全体に印を出す。** 会話の画面の縁から 8px 内側に、info の色の 2px の破線の枠（角は container の丸み）を重ね、中を地の色で薄く覆う。真ん中に、info の薄い地の札で、添付のアイコンと「ここに落とすと添付になります」を出す。
3. **ファイルでないドラッグでは出さない。** ページの中の文字や画像を引きずったときも出さない。
4. **落とし損ねても画面を離れない。** 会話の画面の外にファイルを落としても、ブラウザがそのファイルを開いて画面を移ることはない。
5. スマートフォンでは、ドラッグ&ドロップが出来なくても、添付のボタンは今のまま使える。

### Astryx の部品

- 添付のアイコンは `Icon`（今の添付のボタンと同じ絵）。枠と札は素の要素で、色と丸みは Astryx の token（`--color-border-info`、`--color-info-muted`、`--radius-container`）に合わせる。`FileInput` の dropzone は入力欄のような箱で、会話の画面の全体を覆う形にならないので使わない。
- 印はポインターを受けない。下の会話の画面がドラッグを受け続けるためである。
